# Slug WGSL → Three.js TSL port

The original shader files are preserved **verbatim** in [`third_party/slug-webgpu-reference`](../../third_party/slug-webgpu-reference/README.md), from [diffusionstudio/slug-webgpu at `12d8bdf333263c1340a7ca5de0c36f7f90721be0`](https://github.com/diffusionstudio/slug-webgpu/tree/12d8bdf333263c1340a7ca5de0c36f7f90721be0). The manifest records SHA-256 and Git blob IDs, and both MIT copyright notices are retained. The original HLSL was also inspected at [EricLengyel/Slug `be3c13eb7d63f9e8aa5c583e42d92c374cb91d98`](https://github.com/EricLengyel/Slug/tree/be3c13eb7d63f9e8aa5c583e42d92c374cb91d98).

The runtime is a TSL translation of the default nonzero-fill, no-optical-weight-boost path. It is **not** described as a verbatim mathematical copy where an adaptation is listed below. There is no handwritten WGSL/GLSL production pipeline: Three generates both backends from the same nodes. CPU font preparation, glyph identity, resource ownership, paints, masks and document commands retain their existing owners. The later text-shaper migration changes the CPU font backend while preserving this Three/TSL coverage graph.

## Explicit numerical adaptations

### Stable quadratic evaluation

The reference forms `a=p0−2p1+p2`, `b=p0−p1`, `c=p0` after translating control points by the fragment coordinate, then evaluates `(b±sqrt(max(b²−ac,0)))/a`. MusArt forms `a` and `b` from raw control points before translation, avoiding spurious Float32 curvature on exact straight segments. It evaluates the same ordered roots with `q=b+sign(b)*sqrt(max(b²−ac,0))`, using `c/q` and `q/a`, with a repeated-root fallback. These are algebraically equivalent on the quadratic branch.

The near-linear branch uses the reference's exact `abs(a)<1/65536` cutoff. The coordinate space was checked rather than assumed from the shader's “em-space” label: `src/slug.ts::prepareText` passes raw glyph-bound coordinates unchanged into `tex.xy` (lines455–466), while the object-space positions alone are multiplied by `font.scaleForSize` (lines423–434), with inverse scale used as the Jacobian (lines450–451). MusArt likewise stores unscaled font-design-unit curves and reconstructs that same sample space from raw glyph bounds; its Y-axis reversal changes signs, not units or this absolute cutoff. Finite denominator guards remain explicit. Independent original-outline witnesses cover the stable evaluation on large straight and diagonal glyphs. No artificial diagonal bow from `src/slug.ts::lineToQuadratic` is imported; outline geometry stays exact apart from the pre-existing documented cubic-to-quadratic tolerance.

### Dynamic dilation and affine support

For local point`p`, normalized corner direction`n`, and the active MVP, define `C=MVP*(p,0,1)`, `N=MVP*(n,0,0)`, `s=C.w`, `t=N.w`, and `U=(s*N.xy−t*C.xy)*viewportSize`. The reference scalar is `s²*(s*t+length(U))/(dot(U,U)−(s*t)²)`. MusArt rationalizes this to `s²/(length(U)−s*t)` with finite denominator guards. Three's `viewportSize` reads physical pixels from the **active RenderTarget**, not the CSS canvas.

The scalar is calculated with a normalized diagonal, but MusArt applies it to each signed corner axis (`direction`, with components ±1), rather than translating only along that normalized diagonal. In the isotropic case this already expands each axis by √2 more than the reference diagonal translation, covering the square half-pixel support. Each axis then takes the maximum with half the absolute row sums of the inverse local→pixel Jacobian. That envelope is the exact box-filter footprint for affine 2D transforms, including rotation and shear, and protects independently rounded target axes. This conservative corner expansion is explicitly adapted behavior. The native anisotropic witness uses a14×100 layer rendered to2×10 pixels; glyph curves are unchanged and the authored frame clip remains intact.

### Atlas and packing

The shaders are adapted to MusArt's existing Float32 font-unit atlas. Integer headers/references remain exact below the existing4-million-texel bound. The upstream WebGPU example itself uses RGBA32Float curves and RGBA32Uint bands; the official16-bit packing advice is not applied blindly to a different font-unit/global-index representation.

Band reference lists are sorted by descending maximum ray-axis coordinate, as required by the upstream early exit. Membership overlaps by `unitsPerEm/1024`, following the official Slug guidance; parallel lines remain excluded. The8Float32 curve records retain their original addresses. Optional cap-height pixel snapping is not enabled because it would change authored layout during zoom and motion.

## Verification evidence

The dedicated test reads actual decoded exports in a separate validation page and instruments real read APIs on the production page. With the same fixture and unchanged assertions, the frozen pre-port renderer produces zero stem-interior alpha against reference228 at0.1×; the port produces228 on both WebGPU and WebGL. The independent reference renders the original font path; it is not generated from the TSL result. Validation excludes differing corner-filter approximations and compares the straight stem interior.

The candidate also preserves fractional coverage at0.25×/1× and integer/half-pixel phases; the anisotropic clipped-frame witness produces alpha48 against reference44. Large straight/diagonal outlines pass independent interior/exterior checks on both backends. Generated captures, raw reports, the expected failing baseline and build provenance remain under ignored `artifacts/slug-*`. These are correctness observations, not latency or throughput claims. The final six native cases pass on both backends, including paints, alpha/overlap, masks with a foreground-color witness, effects, multiply blending, grouping and high-density preview/export. A pre-existing sampler-aliasing failure discovered by that regression was fixed independently by giving prepared source/backdrop/mask slots distinct temporary render-target textures. The final reports and source hashes are retained in `artifacts/slug-final-native/`.
