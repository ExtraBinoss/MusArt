# Project thumbnail lifecycle

Project lists contain small manifests and composition summaries. Original assets, history events and thumbnail blobs have separate IndexedDB stores. A visible card loads thumbnail blobs for its active composition and its neighbour through `loadProjectThumbnails(projectId, pageIds)`. It receives a lease containing object URLs; releasing that lease allows eviction. Active URLs are never revoked by the inactive LRU budget (80 entries / 32 MiB). A project/page revision change invalidates the previous URL after its last user releases it.

Thumbnails are native WebP blobs, with quality 0.88 and a maximum edge of 768 pixels. One retained GPU session uses a hard 384 MiB resource budget, matching the editor's capacity for original image inputs (fifty 1280×960 originals alone occupy about 234 MiB). Images and mask assets use identical decoded originals in editor, thumbnails and exports. Effect stacks share the compositor's fixed document-reference plane and GPU mip reduction; input images are never resized specifically for a preview. Every mip level is accounted for, and a document exceeding the budget fails explicitly rather than silently changing its effect content. No Canvas2D composition, JavaScript pixel array or GPU readback is used.

Pixel revisions use SHA-256 over canonical composition paint metadata and cached original digests. Renaming, guides, locks and layout annotations do not invalidate the thumbnail. Original digest retention is bounded to 128 entries / 64 MiB of referenced source strings. Render results are persisted only if the manifest still contains the same project, composition and pixel revision; deletion or a later edit cannot be overwritten by an old asynchronous render.

The paint hash includes renderer schema `gpu-webp-768-88-v3`. The shared fixed-reference effect stack deliberately invalidates previews generated by previous renderers, including persisted project cards. Loading an older manifest refreshes its pixel hashes through a metadata-only compare-and-swap before generation, without changing originals, document write tokens or history. Old pixels cannot become a current cache hit merely because document metadata stayed unchanged. Existing visible leases may remain a temporary fallback until a fresh thumbnail arrives; they never acknowledge a new canonical GPU frame. History fingerprints retain their original schema.

The scheduler observes committed engine project snapshots. React color/geometry previews do not enter its queue. It coalesces changes for 600 ms, requests an idle slot with at least 8 ms remaining, and postpones work during pointer approach, gestures, keyboard input and trackpad activity. An exhausted idle-timeout callback reschedules rather than forcing GPU work. Supported browsers also report queued native input through `isInputPending`. Activity is checked again after asynchronous source preparation and before GPU submissions. There is no idle render loop. At most eight pending project snapshots are retained.

Transient layer/effect and export previews borrow exactly the same retained renderer through `ThumbnailPipeline.preview(key, page, assets, options)`. Their queue deduplicates consumers, bounds pending jobs to 32 and retains at most 512 blob results within 8 MiB. Keys must encode every paint variant and revision; edges distinguish 96-pixel layer previews from export previews sized for their physical presentation footprint. Abort signals and current-origin guards are checked before preparation, before GPU work and before delivery. Consumers own any temporary object URLs they create from returned blobs.

Background previews yield to canonical thumbnails and the 600 ms input quiet period. Visible layer/effect/mask rows request `priority: "visible"`, resuming 100 ms after the last wheel packet rather than waiting 600 ms after pointer movement. Layer-list, canvas and explicit-export work retain that same wheel safety boundary. Visible and canonical thumbnails also wait through held keyboard gestures, including intervals between native key repeats; keyup resumes the queue and blur clears abandoned keys. They precede queued canonical/background work while explicit export retains the highest priority. Explicit export popovers request `priority: "foreground"`; after pointer release they bypass that artificial quiet period and run before queued canonical/background jobs, without interrupting an active render. Held pointers, live wheel bursts and hidden documents still defer all optional GPU work; visibility changes wake the existing queue without polling. Disposal rejects pending consumers, drains active work and then closes the single shared render session.

Before native WebP encoding, the retained frame yields one browser task and checks activity/disposal again. This lets queued input cancel an optional encode before `toBlob` can synchronously flush the canvas. The yield uses native task scheduling when available and one abortable timer otherwise; it does not add another renderer or worker. Once a native encoding call begins, it cannot be preempted; a late result after disposal is rejected. The HTML canvas contract copies its bitmap synchronously at `toBlob` invocation and encodes that independent copy in parallel. Input yielding and the two-encoder admission wait occur before rendering. Native snapshot invocation is synchronous in the same task as the GPU draw, because a WebGL framebuffer may clear at presentation after an await. The retained frame mutex therefore releases after snapshot invocation, with its width/height captured first, while the browser finishes encoding. At most two 96-pixel visible previews overlap their native encoding callbacks; every GPU draw remains serialized through the same frame session. Canonical, background and larger/export previews remain serial. Disposal drains both pending encoders before closing the session. These guards protect scheduling boundaries and do not claim to eliminate unrelated React/layout work during selection.

Ordinary project save/load does not await GPU generation. The explicit `flushThumbnails()` service and automation port first persist canonical changes, then wait until queued thumbnails finish when input is quiet. Tests and headless clients can use it before taking a performance baseline. Runtime disposal cancels pending work, waits for active work and releases its retained session and object URLs.

New project, duplicate-project, colliding portable-import and original mask-asset identifiers use `crypto.randomUUID()`. Their persistence identities remain unique across browser sessions. The pure engine's local identifiers remain suitable for document layers and guides.

The unit suite covers coalescing, selected-page loading, stale result rejection, deletion, activity suspension, resource cleanup, URL leases, revision invalidation, native encoding failures, UUID persistence and StrictMode aborts before the first storage write. Native browser checks confirm resized image orientation on both Three backends and successful WebP decoding. Project-card browser scenarios validate persisted composition previews and the library's CRUD and carousel interactions.

## Layer and attachment previews

Layer rows always pass their explicit artboard ID, including while that artboard is inactive. Their URL identity includes the artboard and attachment variant as well as the paint key. Switching rows or removing an artboard aborts the request and rejects late object-URL allocation. All mounted cards share one lazy visibility observer with the same 32-pixel margin; retiring a generation or rebinding a node rejects queued old observations, and its final subscriber disconnects it. One shared user-visible task admits at most four owned requests. A slow cold request cannot block cached rows behind it, while the limit remains below the bounded GPU queue capacity. Completed blob hits return without optional GPU work, including during input. Actual rendering remains serialized in the one retained session and paused for held pointers, live wheel bursts and queued native input. Visibility and cancellation checks remain at admission and delivery.

A genuine image load starts a 100 ms opacity reveal without delaying the request or readiness signal. A weak per-blob record avoids replaying that reveal when an already displayed cached preview returns; reduced motion skips it. Native drag activity remains held after the browser cancels its pointer stream and releases on drop/end/blur. A canceled `dragstart` releases after bubbling handlers have run, guarded against a newer drag or disposal, because canceled native drags have no later `dragend`.

Effect cards request the real owner composition through the named effect, retaining preceding effects and complete mask dependencies. Mask cards request actual coverage: a temporary isolated white owner over black is processed by the existing GPU mask graph, preserving alpha/luminance mode, inversion, transforms and the source's own effects. Painted ancestor processing is neutralized separately from the privately copied source graph. Inspecting a disabled mask does not enable it in the document. Disabled mask sources and original assets participate in inspection identity, so changed source bytes cannot donate a stale cached mask. These temporary compositions create no additional renderer and perform no GPU pixel readback.

Exact mirrors cover intermediate effects, asset/group masks, disabled-source invalidation, explicit inactive-page image/effect/mask requests, actual queue stale rejection, bounded admission, visible priority and URL cleanup. The native `layer-thumbnails.spec.ts` decodes all three genuine thumbnails on an inactive second artboard in a separate inspection page, compares effect pixels and alpha/matte coverage, and verifies URL revocation after artboard deletion.

`thumbnail-arrival.spec.ts` measures native wheel dispatch to the last actually visible loaded layer thumbnail across two 150-layer AFTERHOURS artboards. Readiness uses `complete` and positive `naturalWidth`; a following frame verifies the same destination and visible identities, without imposing an artificial minimum. This is an image-readiness proxy, not certified decode or physical display time. The regression checks a cold jump below 450 ms, cached returns below 150 ms with no new 96-pixel encodings or WebGPU submissions, unchanged editor React commit counters and zero production pixel readbacks. Its separate 24-packet, 420-pixel native wheel burst records actual delivery clocks, frame gaps, long tasks and mounted rows, and verifies no optional GPU work while the delivered burst is active. It writes environment details and raw frame samples to ignored `artifacts/thumbnail-arrival.json`. Run it against a frozen production build using the performance protocol; these budgets describe this fixture rather than every document or device.

That first cohort explicitly saves and flushes canonical thumbnails before measuring a cold, previously unseen layer viewport. Its retained renderer may therefore be warm. A second case measures the first jump immediately after the first useful main-canvas frame, without saving, flushing, activating another artboard or waiting for top-row thumbnails. It records engine publication, main-canvas readiness and input delay separately in `artifacts/thumbnail-opening-arrival.json`. Natural bootstrap work remains in this workload; the case does not claim a cold browser GPU device. Compare each variant with the same variant on the prior build.

`thumbnail-encoding.spec.ts` delays delivery of genuine native encoding callbacks to verify that differently sized red/blue, effect-stage and mask snapshots retain their own pixels after the shared canvas has rendered later frames. This correctness-only delay is absent from latency cohorts. The case checks one reused GPU canvas, at most two callbacks, genuine decoded colors/coverage and zero production pixel readbacks. The snapshot behavior follows the [HTML canvas `toBlob` algorithm](https://html.spec.whatwg.org/multipage/canvas.html#dom-canvas-toblob).
