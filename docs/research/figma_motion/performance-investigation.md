# Motion performance investigation

This is an implementation investigation, not a completed performance acceptance report. The requested approximately 16 ms interaction/frame budget still has failing cases. The [verification contract](performance-and-verification.md) remains the acceptance authority.

The user's current resource constraint takes priority: continue lightweight implementation and short focused checks only. Checks use one worker, CPU quota 100%, low CPU/I/O priority, bounded heap/memory and a timeout. No further long builds, stress loops or profiling cohorts are authorized by the ongoing investigation. Any indispensable native check is short, serial and closes its owned browser in `finally`; cleanup must also cover timeout failure.

Driver wall time includes deliberate waits and IPC; it is not input latency. Event generated/delivered clocks, handler duration, RAF opportunity, useful rendered frame and GPU acknowledgement are separate measurements. A 60 Hz RAF interval of approximately 16.67 ms does not establish a 16 ms input-to-image guarantee. Queue acknowledgement is not an isolated GPU transfer/bandwidth measurement.

Detailed invalidation tracing substantially amplified some costs. The production latency cohorts use no CPU profiler or tracing. CPU-only profiles and full traces are separate causal evidence. Profiling samples and markers are opt-in and bounded; ordinary playback does not emit those markers.

## Confirmed causes and implemented corrections

| Cause                                                                   | Evidence                                                                                                                  | Correction / status                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reopening a demuxer/decoder for successive forward samples              | Earlier In Bloom source decode accumulated approximately 6120 ms across 12 requests                                       | A retained Mediabunny `samples()` iterator per playing layer; originals remain deduplicated. Cancellation observes actual decoder close and never drains a long video to EOF.                                                                                                                                   |
| Waiting for a complete GPU queue fence after each video copy            | Earlier diagnostic median copy-plus-acknowledgement boundary was 33.9 ms                                                  | At most three VFT/lease slots per stream, four streams, charged to the shared GPU budget. Leases remain alive until actual acknowledgement; exact export settles all outstanding work.                                                                                                                          |
| React/DOM construction on timeline window changes                       | JSX/DOM reconciliation dominated earlier scroll/zoom CPU profiles                                                         | Retain the hidden timeline with React Activity, mount closed popover contents lazily, memoize transport/ruler, and keep their callback/element props stable.                                                                                                                                                    |
| Layout reads between transport subscribers' DOM writes                  | `TimelinePanel.sync` accumulated approximately 196 ms in a four-second CPU-only playback profile                          | Cache horizontal scroll from actual scroll events and local writes. Transport ticks do not read scroll layout. Viewport dimensions come from ResizeObserver.                                                                                                                                                    |
| Optional GPU work competing with playback                               | Thumbnail admission observed effect previews but did not observe Motion playback                                          | Suspend optional thumbnail/preview admission for the whole playback interval; notify admission listeners only on state transitions.                                                                                                                                                                             |
| Synchronous first-use node/material construction during a frame         | Consecutive production baseline recorded a 500 ms first-Play long task and 486.3 ms composition CPU maximum               | Prepare the same scenes, meshes, materials and attachment format with Three's `compileAsync` before drawing. Restore public renderer state before every await; reject stale preparation. The preparation target is one accounted RGBA pixel.                                                                    |
| Opacity-zero Motion sources prepared only upon first appearance         | Future text/video preparation started after Play                                                                          | Prepare Motion text and a bounded set of real video posters/pipelines even at zero opacity. Visible videos have admission priority; total video preparation remains within four streams. Compositing opacity is unchanged.                                                                                      |
| Rebuilding text outlines for continuous layout animation                | In Bloom keys title `letterSpacing`; around 51 text preparations occurred in six seconds                                  | Per-layer outline identity excludes layout. Reuse atlas/material/buffers when glyph identity is unchanged; update placement/bounds data and camera parameters. Rebuild and retire resources when wrapping/clipping changes glyph topology. Native pixel equivalence passes; updated performance cohort pending. |
| Rounding logical NTSC source requests/sample timestamps to microseconds | A focused regression selected frame 1 instead of frame 2 at exactly `2002/30000` seconds                                  | Keep source requests rational and decoded timestamps/durations in the original track timebase. Native `VideoFrame` timestamps remain a separate microsecond API. Twenty-nine focused timing/backend/source/cursor/probe tests and a short actual-codec NTSC witness pass.                                       |
| SDK transparent-video helpers can copy native pixels into JavaScript    | Mediabunny 1.62.1 alpha merger/separator paths use `VideoFrame.copyTo`; generic GPU/Canvas probes do not observe this API | Reject transparent source import/decode before sink creation, and `alpha: "keep"` export before audio/encoder/output setup, with explicit typed localized errors. Opaque VP9 stays supported. Add a direct `VideoFrame.copyTo` probe; a native GPU alpha adapter is deferred.                                   |

The VFT texture budget uses `VideoFrame.displayWidth/displayHeight`, matching Three's allocation dimensions rather than assuming coded and presentation dimensions are equal.

Three's [VideoFrameTexture](https://threejs.org/docs/pages/VideoFrameTexture.html) is the manual WebCodecs-frame bridge. Mediabunny recommends persistent [sequential samples](https://mediabunny.dev/api/VideoSampleSink); separate sink calls are independent. The implementation retains the installed version's demux/decoder and uses a checked, instance-local lifecycle adapter because iterator return alone does not acknowledge native decoder shutdown. No prototype/global patch or alternative decoder is installed.

## Consecutive production warmup comparison

Both runs used In Bloom, the same browser/adapter/viewport, a 400% CPU cap and six seconds of real Play, including the loop boundary. The before/after bundles remain distinct: `prod-media` and `prod-warm0`. These results precede the continuous-text-layout optimization.

| Boundary                                            | Before asynchronous preparation | After asynchronous preparation |
| --------------------------------------------------- | ------------------------------: | -----------------------------: |
| Useful rendered frames observed                     |                             214 |                            252 |
| Composition CPU p50                                 |                          4.8 ms |                         4.1 ms |
| Composition CPU p95                                 |                         49.6 ms |                        14.3 ms |
| Composition CPU maximum, including cold preparation |                        486.3 ms |                        74.4 ms |
| RAF gap p95                                         |                         50.0 ms |                        33.4 ms |
| Useful-image interval p95                           |                         66.7 ms |                        66.6 ms |
| Long tasks during Play                              |              10, maximum 500 ms |               2, maximum 84 ms |

Preparation itself remains measurable work: the new pipeline stage contains asynchronous cold compilation. Moving it out of the synchronous drawing section does not make its elapsed duration disappear. The useful-image interval still fails the requested budget, especially around startup and looping. The steady two-second middle window produced 110 useful images after the change, with a 33.3 ms p95 image interval; this is not a universal 60 FPS pass.

Other production UI measurements after scroll/header fixes recorded p95 RAF gaps of 16.7 ms for timeline scroll and hover, and 16.8 ms for timeline zoom. Native input/dispatch clocks and cold click/menu outliers remain separate acceptance checks. The bare DOM native-input control itself showed approximately 23–26 ms generated-input-to-RAF p95, with approximately 0.7–1.5 ms dispatch-to-RAF p95 in the paired runs; retain those raw results rather than raising application thresholds.

The 200% scope was throttled in 44 of 69 scheduling periods in one video run. A separate 400% run removed that throttling but still exposed application delays. Quota effects contribute to the measurement environment and do not explain away the remaining failures.
