# Motion integration: source inspection and follow-up

Review date: 2026-10-29. This is a **read-only source audit** of the active worktree after the user's M38 resolver/crash/performance report. It did not launch a GPU/browser cohort and provides no latency measurements. Sources are changing under coordinated owners; the findings below are review-time observations, not a claim that every issue remains in the latest revision or has been fixed.

M39 subsequently pinpoints the reported error to pressing **Play in Motion**. A missing thumbnail/export resolver is therefore an additional confirmed code-path gap, not a proven attribution of that particular Play failure. Capture the actual native stack. M40 reiterates frame determinism and no CPU readback; retain the Mediabunny/native-decode → Three GPU split without claiming universal hardware decode.

## Positive boundaries confirmed by inspection

| Boundary          | Observation                                                                                                                     | Limit of the evidence                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Frame leases      | Successful rasterization releases leases in `VideoFrameTextureOwner.withFrame`'s `finally`; failure paths also release/dispose. | Source inspection does not prove a resource plateau under a native codec/driver.                              |
| Decoder admission | Active originals, frame bytes, pending preview/exact jobs and source caches have explicit limits.                               | A hard four-original budget is a current limitation to surface, not an unlimited-video performance guarantee. |

## Required targeted checks

- [ ] A delayed old PlaneResources disposal cannot hide or clear a new owner's ready canvas.
- [ ] Project A → B before React commit uses B's resolver for B's scene; a later A read cannot publish.
- [ ] Active canvas, inactive thumbnail, inspector/selection preview, image export, automation and history replay each resolve their own project's originals or report a deliberate unsupported path.
- [ ] Playback render cost greater than one RAF still makes bounded forward progress; requested/presented timestamps remain visible in diagnostics.
- [ ] Rapid reversing seeks discard stale work, close frames and preserve only the newest target; playback coalescing must not reintroduce stale seek output.
- [ ] Count cold/warm backend opens, decoded/uploaded frames, original storage reads and per-clip GPU fences before claiming smooth forward play.
- [ ] Hide the timeline while a trim, scrub, resize or popup is active: no late edit, portal, captured pointer or duplicate panel remains.
- [ ] Run the licensed mixed-media templates through native GPU rendering and decoded original-source Mediabunny A/V export, then retain failing as well as passing evidence.

The native media work has priority under the shared single-heavy-job coordinator. No result in this document satisfies the ~16 ms target by itself.
