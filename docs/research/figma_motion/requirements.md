# Motion and video requirements

This inventory translates the user's Motion discussion into testable obligations. The authoritative French wording, including tentative ideas and corrections, is preserved in [the verbatim brief](user-brief.fr.md). Assistant suggestions do not become user requirements through repetition.

## Classification and traceability

| Mark  | Meaning                                                                                                                                |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **H** | Explicit user requirement or design instruction; preserve it in the delivery checklist.                                                |
| **P** | Explicit experience target or future direction; preserve it, define its scope and report evidence honestly.                            |
| **D** | Derived acceptance rule needed to make an explicit requirement coherent; identify the proposal rather than attributing it to the user. |
| **G** | Existing repository guardrail; it constrains implementation independently of this feature request.                                     |

[M1](user-brief.fr.md#m1) introduces video/camera and time-driven properties; [M2](user-brief.fr.md#m2) prioritizes video effects, deterministic export and the separate Timelapse role; [M3](user-brief.fr.md#m3) and [M5](user-brief.fr.md#m5) explain the layer/compositing and workflow concerns. [M4](user-brief.fr.md#m4) rejects premature coding during exploration. [M6](user-brief.fr.md#m6) subsequently authorizes an isolated implementation with detailed requirements and supplied screenshots. [M7](user-brief.fr.md#m7) adds the documentation, research and delegated-checklist preparation now in progress. [M8](user-brief.fr.md#m8) fixes Mediabunny as the exporter and asks for questions where decisions remain. [M9](user-brief.fr.md#m9) explicitly requires instant-feeling scrubbing backward and forward. The user answers in [M10](user-brief.fr.md#m10), [M11](user-brief.fr.md#m11) and [M12](user-brief.fr.md#m12) settle Static base-design behavior, automatic local proxies and source-video audio controls respectively. [M13](user-brief.fr.md#m13), [M14](user-brief.fr.md#m14) and [M15](user-brief.fr.md#m15) confirm active-artboard-only playback, extending duration for longer imported video without shortening existing tracks, and counting every layer receiving a track, including groups and descendants. [M16](user-brief.fr.md#m16) schedules camera/live input for the next step after video and timeline stabilization. [M17](user-brief.fr.md#m17) chooses an Export split button with a small downward chevron and a Timelapse export option. [M18](user-brief.fr.md#m18) narrows Timelapse to a simplified dialog that fits the complete creation replay into a requested final duration of 1–30 seconds. [M19](user-brief.fr.md#m19) explicitly requires a generic, headless-capable animation engine and readable, maintainable, smooth implementation.

Every build task must reference these stable IDs and record its actual verification. A checkbox, authored test or mockup is not proof that the behavior has passed.

## Existing engineering guardrails

## Shared layer dragging follow-up (M93/M94)

Both the timeline's layer gutter and the whole clip body must support vertical
layer reordering, sharing the Layers panel's session, projection, canonical
validation, live cues and edge-scroll velocity. The clip body locks its intent
after a small movement threshold: vertical movement reorders, horizontal movement
retimes the clip. Keyframes and trim handles retain their own timing gestures.
Cross-view dragging uses one engine-scoped ownership model, not fabricated
DragEvent/DataTransfer objects. Pixel motion stays imperative; React snapshots
change only with semantic projection or phase. Completion commits once, while
cancellation or stale ownership restores the original state. Unsupported timed
hierarchy changes must be explained rather than silently bypassed.
