# Performance research and UI source audit

Researched 2026-10-29 against official documentation and the installed workspace APIs: Mediabunny 1.62.1, Three.js 0.186.1, React 19.3 and Motion 14.7.1. Documentation can describe a newer API; check the installed implementation before adopting it. This page separates documented behavior, source observations and proposed changes. It does not certify a frame-time budget.

## Media selection and GPU composition

| Official finding                                                                                                                                                                                                                                         | Implication for MusArt                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VideoSampleSink recommends `samples()` for sequential media access. `samplesAtTimestamps()` optimizes ordered sparse requests rather than repeatedly decoding packets. [Mediabunny API](https://mediabunny.dev/api/VideoSampleSink)                      | Retain a bounded forward iterator per independently timed clip; repeated one-timestamp calls do not establish a warm sequential decoder. Different source in-points on clips sharing an original need separate timing lanes. |
| Sinks are track-scoped and calls are independent; manually owned iterators need cleanup. Presentation order differs from decode order. [Media sinks](https://mediabunny.dev/guide/media-sinks)                                                           | Deduplicate immutable bytes/indexes while preserving bounded decoder/iterator ownership. B-frames and reversing seeks still require exact PTS handling and stale-output rejection.                                           |
| A `toVideoFrame()` result must be closed separately from its sample; `copyTo()` transfers pixel data into JavaScript buffers. [VideoSample](https://mediabunny.dev/api/VideoSample)                                                                      | Use explicit native frame leases. Keep frames alive until actual GPU consumption; avoid production pixel copies/readbacks.                                                                                                   |
| VideoFrameTexture is designed for manually supplied frames, including WebCodecs output. [Three.js API](https://threejs.org/docs/pages/VideoFrameTexture.html)                                                                                            | Mediabunny/native selection and Three GPU composition are complementary. Changing to a live HTMLVideoElement clock does not establish deterministic export sampling.                                                         |
| Native codec availability depends on the browser. [Supported codecs](https://mediabunny.dev/guide/supported-formats-and-codecs)                                                                                                                          | Detect real support and preserve codec/HDR diagnostics. Do not claim every source decodes on the GPU or in every browser.                                                                                                    |
| Material precompilation can reduce first-use shader stutter. Textures and materials have separate disposal obligations. [Renderer](https://threejs.org/docs/pages/Renderer), [disposal](https://threejs.org/manual/pages/how-to-dispose-of-objects.html) | Separate cold compile from warm frame cost, retain reusable graphs and release every owned resource. Old disposal must not overwrite a newer canvas owner.                                                                   |

These are engineering inferences from the documented APIs, not a benchmark comparison proving one library is universally faster. The actual application keeps Three.js WebGPURenderer/TSL and its WebGL fallback; Mediabunny owns demux/frame selection and export.

## React, visibility and Motion

| Official finding                                                                                                                                                                                                                     | Application rule                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Motion favors transform/opacity for presence. Layout properties can cause broader layout/paint, and extra compositor layers consume memory. Acceleration varies by browser. [Performance guide](https://motion.dev/docs/performance) | Reserve the final panel dimensions once. Animate its transform/opacity and measure the actual compositor result; do not add `will-change` to every element.                                                                                                   |
| Motion values update DOM styles outside React rendering. [Motion values](https://motion.dev/docs/react-motion-value)                                                                                                                 | Keep playhead and continuous numeric preview publication imperative. Measure any remaining animated color/control leaf renders separately.                                                                                                                    |
| External-store snapshots must be cached/immutable; `Object.is` determines change. Stable subscribe functions avoid resubscription churn. [React API](https://react.dev/reference/react/useSyncExternalStore)                         | Localize Jotai visibility and expose scalar/stable snapshots. A fresh object/array on every read can cause work despite unchanged data.                                                                                                                       |
| Activity preserves DOM/state, cleans Effects while hidden and restores Effects on reveal. Hidden children may still render new props at lower priority. [Activity](https://react.dev/reference/react/Activity)                       | A bounded retained timeline can avoid repeat DOM mounting. Complete its exit before `hidden`, disable interaction immediately, retain at most the current project/page and freeze hidden panel props where appropriate. Verify observer/subscription cleanup. |
| AnimateActivity currently requires a separate Motion+ early-access package. [Motion documentation](https://motion.dev/docs/react-animate-activity)                                                                                   | Do not assume it is part of the installed free runtime. The current patch composes stable React Activity with existing Motion controls.                                                                                                                       |
| CSS content visibility can skip browser rendering without removing the DOM. [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility)                                                          | CSS hiding alone does not establish that subscriptions, decoders or GPU work stopped. Use actual lifecycle cleanup; avoid adding containment blindly to a small editor subtree.                                                                               |

## Source audit: candidates for native attribution

| Area                     | Observation at review                                                                                                                                                                           | Follow-up / status                                                                                                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dock                     | Earlier hide/show removed and rebuilt the whole timeline.                                                                                                                                       | Activity retention patch preserves one scope, lazy first mounting, state/DOM and hidden cleanup. Focused/native performance checks are pending for this new patch.                                                    |
| MotionDiamond            | Each tick searched keys and rewrote unchanged attributes/title.                                                                                                                                 | Patch caches property tracks, binary-searches key membership and deduplicates presentation writes. Authored test expects no attribute mutation across 60 non-key seeks; not yet run during the reserved media cohort. |
| Color leaf fields        | Primitive snapshots prevent unrelated renders, but animated color values can legitimately change every frame.                                                                                   | Profile those leaves, rather than inferring cost solely from zero App/Inspector commits. Numeric fields already use imperative presentation.                                                                          |
| Timeline geometry        | Playhead/autofollow callbacks read viewport dimensions then mutate scroll/position.                                                                                                             | Root traced causal geometry-read cost and is replacing repeated reads with ResizeObserver-cached metrics. Native before/after remains required.                                                                       |
| Virtualization / shadows | Timeline guards vertical updates by row and horizontal windows by coarse range. ScrollShadow now uses direct child-list observation plus ResizeObserver, without subtree attribute observation. | Keep horizontal auto-follow out of vertical React updates. Verify actual bounded DOM counts and observer costs in the trace.                                                                                          |
| Hidden UI                | The searched CSS-hidden nodes were mostly labels/icons/hue/diamonds; no broad force-mounted heavy tabs were found.                                                                              | Do not attribute lag to hidden panels without evidence. Activity cleanup and real mounted/visible counts are separate checks.                                                                                         |
| Inactive artboards       | One backdrop DOM node remains per artboard; preview reads are visibility-gated.                                                                                                                 | Consider DOM virtualization only for a measured large-artboard workload, while preserving selection/accessibility.                                                                                                    |
| Loading / glass          | Canvas reveal uses a short filter/clip animation; glass controls have small backdrop-filter surfaces.                                                                                           | Profile cold versus warm paint separately. These are candidates, not proven steady-state bottlenecks.                                                                                                                 |
| Repeated errors          | A new identical error notice per failed frame can cause root state updates and restart expiration repeatedly.                                                                                   | Pause/mark failed playback and publish errors by source/origin generation. Do not suppress a real failure or repeatedly flood the UI.                                                                                 |

The preceding resolver/disposal/source findings are tracked in [integration-audit.md](integration-audit.md). The media owner reports a retained sequential iterator per video layer, with original bytes deduplicated; that addresses the cold-per-request pattern. It does not remove the separately measured GPU-completion cost.

## Measurement boundaries

React Profiler duration covers a subtree and adds overhead; it is not an exclusive per-component/browser/GPU cost. Use matching boundaries and avoid adding nested subtree totals. [React Profiler](https://react.dev/reference/react/Profiler)

Chrome's call tree/Bottom-up/rendering tracks distinguish script, layout, paint and composite work. Detailed paint/selector instrumentation itself slows a recording. Run attribution and clean latency cohorts separately, with matching frozen source/maps and named interaction windows. [Performance reference](https://developer.chrome.com/docs/devtools/performance/reference), [recording options](https://developer.chrome.com/docs/devtools/performance/overview)

| Boundary                       | Evidence to retain                                                                                                                 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Input → feedback               | Event arrival, handler, visible control/playhead response and long tasks for reveal/hide, play/pause, zoom and scrolling.          |
| Requested time → correct frame | Composition time, source PTS, decode admission/output, GPU submission and actual presentation acknowledgement.                     |
| React and DOM                  | Major-root counters plus timeline/color leaves, actual mounted/visible rows, mutations and hidden subscriptions/observers.         |
| Media/GPU                      | Decoder/backend starts, frame leases, uploads, completion fences/ring occupancy, cache bytes and real readback hooks.              |
| Lifecycle                      | Project/source switch, cancelled seek/export, inactive artboard and teardown leave bounded or zero owned resources as appropriate. |

Root's interim **development** diagnostics reported approximately 12 fps and long tasks around 806 ms reveal, 150 ms hide and 381 ms scroll. These failed the requested experience. Provider timing and a median GPU fence around 33.9 ms are diagnostic sub-boundaries reported by the media owner, not end-to-end production distributions. Functional UI passes, zero readbacks and zero major-root commits do not turn these timings into a performance pass. Root is collecting detailed interaction traces, then a clean production cohort after fixes. No release/performance sign-off is claimed.
