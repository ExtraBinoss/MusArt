# Motion performance and verification plan

Status: **research and proposed acceptance protocol**, October 29, 2026. No Motion/video performance cohort has been run and no result below is a passing measurement. The user requires fluid heavy compositions, roughly 16 ms or better work/frame, and exceptionally responsive forward/backward scrubbing. Mediabunny must export original media; automatic local preview proxies and basic source audio are approved. Play advances only the active composition. Camera/live capture is user-deferred until file video and timelines stabilize; camera-specific fixtures below are roadmap verification, not first-delivery gates.

Use the repository's [reproducible performance protocol](../../performance/protocol.md), [50-image rendering protocol](../../rendering/performance-protocol.md) and [storage rules](../../performance/storage.md). This page adds Motion-specific metrics and fixtures; it does not replace existing gesture/resource gates.

## A performance claim needs an envelope

Record browser/OS, real adapter/backend, driver, CPU, RAM, viewport/DPR, display refresh, power mode, production executable/source maps, source diff, fixture hashes and enabled quality settings. Record decoder/encoder codec, hardware-acceleration evidence where available, source size/resolution/PTS/GOP pattern, active media count and proxy status. A requested acceleration hint is not proof that a hardware decoder was used.

Current photographic load results are not a Motion baseline: the existing 50-image/100-effect workload records warm move p95 51.8 ms and effect update p95 47.8 ms on Chromium 156/Linux/Intel Xe-LPG. Its scope and historical evidence remain in [the rendering protocol](../../rendering/performance-protocol.md). Reaching the user's tighter Motion goal therefore requires measured work on evaluation, dynamic invalidation and effect cost. Do not present a static-layer pan result as proof that all effects can animate within one frame.

| Term                  | Required interpretation                                                                                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 16 ms goal            | Proposed critical-path budget around a 60 Hz frame opportunity, not a universal guarantee for every input size/device. At 120 Hz the presentation interval is about 8.33 ms.                      |
| Deterministic         | The same frozen document, source revision, exact output time and seed select the same evaluated state and source samples, independent of playback history or machine speed.                       |
| Encoded identity      | Native codecs/GPU backends need not produce byte-identical files. Verify authored samples, timestamps and decoded results with justified tolerances; never substitute a file-size-only assertion. |
| Instant-feeling scrub | Immediate input/playhead acknowledgment **and** fast correct-frame arrival, measured separately. Updating the ruler while leaving an old video frame visible is only the first half.              |
| Heavy composition     | A named, hashed fixture with explicit effects, dimensions and source counts. The phrase alone is not reproducible.                                                                                |
| Native correctness    | Real browser decode, Three rendering and decoded exported files. DOM mocks and synthetic renderer counters cannot establish these.                                                                |

`requestAnimationFrame` schedules before repaint; its interval follows display refresh and browser scheduling. It is not a 16 ms performance floor to defeat with a faster timer. Compute playhead time from a monotonic anchor and keep per-frame work short. `requestVideoFrameCallback` can schedule work for newly presented native video frames and supplies media timing; it can still arrive late and must not drive exact offline export. [Animation-frame scheduling](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), [video-frame scheduling](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback).

## Measure distinct boundaries

| Metric                       | Start → end                                                                   | What it proves / limitation                                                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native input queue           | Generated input timestamp → application capture/dispatch                      | Browser/native backlog; preserve generated and dispatch clocks, packet coalescing and a matched minimal-DOM control.                                      |
| Playhead response            | Dispatch → updated playhead/time label at the next presentation opportunity   | Immediate transport response. Record exact target time and generation; this does not prove video pixels changed.                                          |
| Core evaluation              | Exact target admitted → compiled frame plan ready                             | Timeline/easing/interval cost without decode/GPU time. Do not include a full-document snapshot in the measured path.                                      |
| Decode queue wait            | Latest target admitted → required decode work begins                          | Whether stale sequential work delays a new direction.                                                                                                     |
| Source acquisition           | Decode request → usable sample lease with selected original/proxy PTS         | Includes indexed seek and decode; split metadata/index cold work from warm lookup.                                                                        |
| GPU preparation              | Lease ready → affected GPU graph ready/submitted                              | Includes uploads/invalidated effects, not necessarily actual GPU completion.                                                                              |
| Correct-frame acknowledgment | Dispatch → renderer acknowledges target generation/time/source identities     | Required canvas work was submitted for the intended request. Follow with a browser presentation opportunity; do not call it a physical display timestamp. |
| Pixel witness                | Requested target → isolated validation observes expected frame marker/content | Confirms the right decoded frame rather than a stale acknowledgment. Test-only readback must be outside production counters.                              |
| Frame pacing                 | Consecutive useful presentation opportunities and current media-time error    | Detects judder/dropped/repeated frames; report source FPS separately from display Hz.                                                                     |
| Audio drift                  | Audible sample position → corresponding composition/video time                | Device/output clock and decode/queue lateness, using timestamped impulse/visual-marker fixtures.                                                          |
| Persistence                  | Request → actual IndexedDB transaction completion                             | Saved state, distinct from proxy/thumbnail preparation or a UI toast.                                                                                     |
| Export                       | Frozen capture → first frame / progress / final decode-verified file          | Report decode, GPU, encode, mux and target-write components plus throughput and peak memory. Real-time speed is not required for exact output.            |

Report sample count, p50, p95, p99, maximum, missed deadlines, repeated/dropped frames and every failure. Preserve raw samples and deterministic seek sequences. Percentiles need enough observations: aim for at least 1,000 warm interaction/frame samples, while reporting each expensive cold case and cohort count independently. A tiny sample set does not establish a stable p99.

## Proposed budgets to validate in the first spike

These are **candidate engineering targets**, not measured values or already accepted relaxation of the user's request. Freeze the representative device/envelope before turning them into gates. Existing repository pan/wheel comparison rules remain in force.

| Domain                           | Initial target on the named 60 Hz reference envelope                                                       | Failure interpretation                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Compiled evaluation              | p95 ≤ 2 ms; no whole-project validation/clone per frame                                                    | Profile descriptors, segment lookup, dependency closure and allocation.                                                                          |
| Main-thread frame work           | p95 ≤ 4 ms for transport/evaluation/submission glue                                                        | Leave time for input/style/presentation; never confuse async submission return with GPU duration.                                                |
| Heavy active-composition preview | Useful-frame pacing p95 around 16.67 ms; preserve p99/max and source-time error                            | Count every miss. Determine whether decode, effect passes, uploads or UI dominates before adding quality controls.                               |
| Scrub playhead response          | Dispatch → next frame opportunity p95 ≤ 16.67 ms                                                           | Decode/proxy preparation must not block this. Record generated-input latency and same-cohort control as well.                                    |
| Hot cached scrub pixels          | Dispatch → correct acknowledged/rendered target p95 ≤ 16.67 ms                                             | A timestamp-only/old-frame update fails.                                                                                                         |
| Warm proxy seek pixels           | p95 ≤ 33.34 ms; report direction reversals and p99/max separately                                          | A starting optimization target, not permission to hide stalls or rename a slower seek “instant.”                                                 |
| Cold original/proxy/index seek   | Measure all latency components and worst case before setting its device/codec budget                       | No passing claim until the spike establishes a bounded supported envelope and correct preparing/error UX.                                        |
| Long tasks                       | Zero attributable ≥ 50 ms tasks in steady playback, scrub, trim or property gestures                       | Profile task attribution; do not delete outliers from reports.                                                                                   |
| Editor React                     | Zero per-frame commits in App, Inspector, CanvasArea, EditorCanvas and EditorScene                         | Mode/selection/one completed authoring edit may legitimately commit once. Timeline frame positions/time labels also use imperative presentation. |
| Production GPU image readback    | Zero actual WebGPU read maps, WebGL readPixels and Canvas2D pixel reads attributable to composition/export | Native encoding and initial source preparation remain distinct; test validation is isolated.                                                     |
| Resource growth                  | No growth proportional to elapsed playback frames; explicit byte/count ceilings                            | A flat JS heap alone does not account for native decoded frames or GPU resources.                                                                |
| History/persistence              | Zero authored commands/history entries/save writes caused by playback or seek                              | A completed track/key/trim edit has one transaction/undo entry.                                                                                  |
| A/V                              | No cumulative drift; decoded offset bounded by declared sample/timebase quantization                       | Include encoder priming/padding and native preview latency rather than silently shifting assertion windows.                                      |

All resource ceilings must be concrete configuration before implementation is considered complete. The current 384 MiB GPU cap remains in force; add distinct decoded-frame/PCM/source-range/proxy/output-buffer budgets. Do not subtract hidden video textures from GPU accounting to keep a report green.

## Scrubbing is its own critical domain

| Seek pattern                     | Cold/warm variants                                        | Required assertions                                                                                                            |
| -------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Forward contiguous               | Already decoded neighborhood vs first access              | Coalescing does not delay the playhead; correct PTS arrives and queue stays bounded.                                           |
| Backward contiguous              | Short-GOP proxy vs long-GOP original                      | No forward-drain requirement; restart from an indexed access point and reject late old output.                                 |
| Rapid direction reversal         | Alternate immediately before/after a GOP boundary         | Every generation is identifiable; the newest request wins and obsolete frames are closed.                                      |
| Random access                    | Seeded targets across the full clip and beyond warm cache | Exact selected sample, no unlimited full-file scan/read, separate cold-index cost.                                             |
| Pointer burst                    | Native inputs faster than decode/render throughput        | Bounded one-latest pending target, capture/playhead latency remains measured, no backlog playback after release.               |
| Repeated identical target        | Source still frame / repeated VFR PTS                     | Reuse the sample/resource without reupload or recompiling unchanged effect graphs.                                             |
| Mode/artboard/delete during seek | Delayed decoder/provider completion                       | No stale canvas/audio/proxy adoption, no deleted media resurrection.                                                           |
| Release then Play/export         | Latest request still decoding                             | Play starts from the chosen target; export independently evaluates exact original samples, never UI's last acknowledged proxy. |

Instrument requested time, request generation, admitted decode, access-point time, decoded PTS, provider cache hit/miss, proxy/original identity, presentation acknowledgment and closure reason. Test cancellation at decode, upload and encode boundaries. A fake decoder is useful for deterministic race tests; only the native fixture establishes actual seek feel and correct pixels.

Automatic proxies need separate measurements for generation time/CPU/peak memory, first useful preview, bytes written, index adoption, cancel responsiveness and storage quota failure. They run outside active gesture/export competition and expose honest progress. A proxy cache miss is visible as pending media, never a false successful frame. Verify a fast proxy with a deliberately poor spatial resolution still exports the untouched original at full requested quality.

## Generic/headless equivalence and simple Timelapse gates

M19 / ENG-01 / ENG-02 requires a generic, reusable animation engine and readable implementation; these are acceptance domains, not a browser-only performance optimization. M18 / HIST-03 adds the simple Timelapse flow. The public headless API is mandatory; new CLI operation names are proposed convenience adapters. Test authoring/evaluation in **plain Bun and a supported Node runtime without a browser, DOM shim, React, GPU or storage**. Native rendering/encoding remains a real browser capability through the same reusable packages/render Three/Mediabunny implementation with injected media/font/output adapters; the headless host must not import or mount the editor. See [the API proposal](architecture.md#generic-engine-and-headless-contract) and T18 in [the build checklist](build-checklist.md).

| Check                          | Required evidence                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pure package import            | Real Bun/Node smoke processes import the supported package entry without accessing browser globals or launching Chromium. Record versions and runtime entry; Bun's acceptance of TypeScript exports does not prove Node compatibility.                                                                                                                                        |
| Scripted authoring             | The same explicit IDs/project fixture and command list produce equivalent validated timelines, serialized values, errors and undo/redo in Bun, Node and the browser. First-population acknowledgment uses the same counted/fingerprinted plan.                                                                                                                                |
| Property/easing coverage       | Every registered parameter class, incoming easing and discrete rule is exercised through the public API. No separate CLI/effect interpolation switch or DOM-backed easing implementation.                                                                                                                                                                                     |
| Random-order evaluation        | Evaluate matched rational times in forward/reverse/seeded-random order; compare effective property/interval/media-request plans exactly, including FPS boundaries and long durations.                                                                                                                                                                                         |
| Preview/headless frame parity  | The browser interactive path and headless browser adapter consume matching plans/source PTS. Native marker pixels, masks/groups/effects/color and original/proxy boundaries agree under declared backend/codec tolerances.                                                                                                                                                    |
| Real video export              | A minimal headless browser invokes the public packages/render exporter without importing/mounting the editor or reading current UI selection; it uses originals and Mediabunny A/V mux, producing decoded frame/audio evidence matching interactive export. Cancellation/failure closes browser, frame, decoder and target resources. Any added CLI verb calls this same API. |
| Readability                    | Independent review checks small responsibility modules, short entry points, clear names/units, typed registries, explicit lifetime ownership and exact test mirrors; no duplicated UI/core/CLI time model, giant switches, empty wrappers or hidden browser dependencies.                                                                                                     |
| Adapter performance            | Compare matching core evaluation distributions in supported runtimes separately from native media/GPU/export throughput. Serialization/IPC must be measured rather than hidden inside “headless overhead.”                                                                                                                                                                    |
| Timelapse modal                | Native Export dropdown opens a simple final-duration dialog, accepts 1 and 30 seconds, rejects nonfinite/out-of-range values, and shows truthful progress/cancel/errors. It does not recreate the complete Animate interface.                                                                                                                                                 |
| Automatic full-history mapping | Both first and final recorded creation states appear in the selected output duration; speed is derived automatically. Seeking/exporting must not mutate the recorded history or authored Motion duration/keys.                                                                                                                                                                |
| Timelapse exact end            | Decode 1-second and 30-second outputs at integer and fractional FPS; test non-frame-aligned duration, final sample/mux rounding, selected final state and true file end within the declared native timebase. No hidden rounding beyond the 30-second limit.                                                                                                                   |
| Independent export models      | Timelapse applies its explicit history-to-duration mapping; Motion samples authored time at output-frame times and is not capped at 30 seconds. A long Motion fixture must remain exportable under separate documented resource limits.                                                                                                                                       |

Keep pure frame-plan comparisons separate from codec/GPU pixel tolerance. Neither runtime equivalence nor a successful headless API/CLI completion proves rendered content without native output inspection. These cases are authored acceptance requirements until the implementation and actual executions exist.

## Functional and failure gates before a performance claim

| Domain              | Focused checks                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact time          | Rational FPS, long duration, negative/nonzero source PTS, VFR, duplicate timestamps, half-open bounds, integer overflow, end marker, random-order seek and repeated evaluation.                                |
| Model and migration | Old imports default Static; initialized-empty timeline survives; count/confirm CAS; all mode transitions preserve keys; duplicated IDs remap; broken targets/types/times/import limits reject clearly.         |
| All effects         | Registry coverage enumerates every effect-owned setting/common property; native representative values alter pixels, conditional/discrete controls hold correctly, seeded randomness is seek-order independent. |
| Editing/history     | First diamond, later-time edit auto-key, base edit in Static, undo/redo, one-entry trim/move/multi-edit, Escape cancellation, locks, multi-selection and pointer loss.                                         |
| Hierarchy/masks     | Ancestor interval intersections, nested transformed groups, inactive mask-source semantics, copy/paste/delete/reparent, dynamic source invalidation and isolated static subtree reuse.                         |
| Native pixels       | Rotation/flip/pixel aspect, alpha/premultiplication, color range/transfer and authored-density effects at preview/export resolution on WebGPU and genuine Three WebGL fallback.                                |
| Audio               | Embedded audio preserved, per-clip mute/volume, overlaps, source trim, offset tracks, sample-rate/channel conversion, gaps, first/last sample, priming/padding and long A/V drift.                             |
| Proxy boundary      | Original revision/fingerprint mismatch, partial output, generation cancel, quota/codec failure, eviction/rebuild and explicit original-only exported content.                                                  |
| Resource lifecycle  | Close samples plus converted native frames separately; hold leases through delayed GPU/encoder consumption; dispose inputs/output/context resources on every exit.                                             |
| Errors              | Unsupported/corrupt/truncated media, missing original, decoder crash, GPU loss, failed storage transaction, export cancel/write rejection and late results after deletion. No simulated success.               |
| Export              | Mediabunny output sample times/count/duration/dimensions, decoded representative/all marker frames and audio, repeat export after arbitrary scrubbing, cancellation and original/proxy revision capture.       |

Use exact mirrored source tests as subsystems are added; declaration-only files are exempt. Pure core tests prove values, commands and invariants. Native browser tests prove media/GPU/gestures/decoded output. Mocks never replace the latter. Follow the existing 600-line limit and keep executable tests outside `src/`.

## Running and preserving a cohort

1. Finish a narrow implementation milestone and its relevant static/focused unit tests. Review source diff and the exact fixture; no full coverage/build loop for each UI tweak.
2. Reserve **one** heavy CPU/browser/GPU slot across agents. Use one browser worker, low priority and explicit CPU/memory limits following [the shared protocol](../../performance/protocol.md). Stop competing compilers/coverage/proxy/export work unless the fixture intentionally measures that overlap.
3. Freeze a production build and source maps in ignored `artifacts/`. Keep the Motion development app on **6110**, with strict-port failure; leave the existing 6100 app untouched. HMR/dev measurements are diagnostic, not final latency claims. A frozen performance preview may use a separate documented port.
4. Confirm HTTP reachability, foreground the measured tab, install probes before application load and record real backend/adapter. Separate bootstrap/codec/index/compilation from warm playback. Do not remove cold samples.
5. Run one named scenario at a time. Preserve input counts/clocks and a same-cohort control where native injection overhead matters. Stop immediately on memory/swap pressure; report an unavailable backend or scope-limit failure truthfully.
6. Keep screenshots, native decoded output, JSON metrics, trace/profile files, executable/maps, command and environment under a unique ignored cohort directory before another run overwrites them.
7. Fix the attributed failure and rerun only affected checks; broaden to the appropriate GPU/storage load cohort for the subsystem touched. Do not raise timeouts, alter fixture difficulty or weaken assertions to turn failure into success.
8. Publish observations with exact scope, unresolved limits and raw failure flags. Independent domain audit follows implementation when requested; full frozen CI/release gates remain separate from these focused development checks.

Suggested report fields: `sourceCommit`, `workingDiffHash`, `buildHash`, `fixtureHash`, `browser`, `os`, `cpu`, `ram`, `adapter`, `backend`, `displayHz`, `viewport`, `dpr`, `sourceCodecs`, `sourceDimensions`, `proxyState`, `activeSources`, `limits`, `sampleCount`, `p50`, `p95`, `p99`, `max`, `missedDeadlines`, `staleDiscards`, `readbacks`, `reactCommits`, `peakGpuBytes`, `peakDecodedBytes`, `peakPcmBytes`, `storageReadsBytes`, `storageWritesBytes`, `audioDrift`, `failures` and artifact paths. Separate distributions by operation, cold/warm state and original/proxy; a single average is insufficient.

## Milestone acceptance checklist

- [ ] Generic core authoring/evaluation works in real Bun and Node smoke processes with no browser/DOM/React/GPU/storage dependency.
- [ ] Interactive and headless consumers share the same validated commands, compiled evaluation, frame/source requests and real Three/Mediabunny export behavior.
- [ ] Independent code review confirms readable responsibility modules, typed extension points and no duplicated animation logic.
- [ ] Simple Timelapse export honors 1–30 seconds and complete-history autospeed without imposing that cap or mapping on Motion.
- [ ] Core evaluation and every property descriptor pass exact-time, discrete/easing and command/history tests.
- [ ] First population, retained mode toggles and active-only playback match the confirmed product contract.
- [ ] Native source upload/lifetimes/color/orientation are verified on both render backends.
- [ ] Hot/cold forward/backward/random scrub reports contain both immediate playhead and correct-frame boundaries.
- [ ] Automatic proxy work is cancelable, bounded and revision-safe; export proves original-only sampling.
- [ ] All photographic effects process moving input and keyed settings correctly; unrelated static work remains cached.
- [ ] Source audio survives trim/mute/volume/overlap and decoded Mediabunny export with bounded A/V error.
- [ ] No per-frame editor React commits, document/history writes or production GPU image readbacks occur.
- [ ] Fifty-image/effect plus media cohorts record true hardware/backend, p50/p95/p99/max and every missed target.
- [ ] Long-run and adversarial cleanup show bounded resources, no stale adoption and no deleted-data resurrection.
- [ ] Measured supported device/workload envelope and unresolved performance limits are documented before any “smooth” or “instant” claim.
