# Motion decisions and open questions

This register separates the user's settled choices from implementation proposals and unresolved details. It is a planning input, not a blanket approval gate. In M8 the user explicitly asks for questions when decisions remain. Preserve asked questions as pending until the user answers; continue independent research and preparation in the meantime. All eight product questions asked so far have received explicit answers, recorded below and traced to M10–M17. No user answer remains pending. Subsequent explicit instructions in M18 narrow Timelapse to a simplified 1–30-second dialog; M19 requires a generic headless-capable animation engine and readable, maintainable code.

The [verbatim brief](user-brief.fr.md) is authoritative. The [requirements inventory](requirements.md) supplies stable IDs for the build checklist.

## Proposed defaults to make the model coherent

These are engineering/product proposals, not additional user quotations. Architecture and UX research must reconcile them before dependent tasks implement incompatible assumptions.

| ID    | Proposal                                                                                                                                                  | Reason and validation                                                                                                                                                                       |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PD-01 | Treat timeline rows as a temporal view of existing layer/effect identities, not a duplicate scene tree.                                                   | Preserves compositing order, groups, attachment identity and selection. Test reordering, deletion, duplication and clipboard operations against one canonical model.                        |
| PD-02 | Store an explicit “initialized” state independent of the current Static/Motion mode.                                                                      | Distinguishes first adoption from later mode switches, including a timeline which currently contains no tracks. Test empty-artboard initialization and all repeated-switch paths.           |
| PD-03 | Represent default whole-duration presence as following the composition boundary, while retaining explicitly trimmed ends.                                 | Extending the artboard can keep adopted still content present without overwriting authored trims. Verify extension, shortening, undo and round trips.                                       |
| PD-04 | Make mode conversion, initial adoption and video insertion one validated undoable transaction.                                                            | Declining or failing conversion must not leave new media, mode metadata or partial tracks behind. Decoder preparation can happen outside that transaction with stale guards.                |
| PD-05 | Keep playback/playhead updates outside persistent document commands and large React subscriptions.                                                        | Playing does not generate thousands of history entries or repeatedly rebuild the inspector. User-authored keyframe or trim gestures commit once.                                            |
| PD-06 | Use one explicit temporal evaluator for preview, seeking, still-at-time export and deterministic video export.                                            | Prevents an export-only easing or interval interpretation. The external scheduler supplies time; pure evaluation reads no wall clock.                                                       |
| PD-07 | Define numeric/color interpolation and discrete values through typed property metadata.                                                                   | All catalogued effects remain applicable; boolean/select/seed/structural settings cannot be made invalid by indiscriminate interpolation.                                                   |
| PD-08 | Decode recorded media by presentation timestamps and bounded ownership; let preview coalesce obsolete work while export waits for exact required samples. | Provides responsiveness without converting a dropped preview frame into a missing export frame. Test seeks, VFR inputs, cancellation and decoder cleanup.                                   |
| PD-09 | Keep image-only Static compositions on demand; schedule work only while authored animation, video or live input requires a new frame.                     | A time-capable project must not make every inactive artboard render continuously. Validate idle GPU submissions and background scheduling.                                                  |
| PD-10 | Store camera bindings outside portable device handles; persist recorded camera footage as normal media assets.                                            | A future reopened camera cannot reproduce a previous live session. Test disconnect, permission denial, stopping tracks, recording finalization and reopen behavior in the camera milestone. |
