# Motion audio

Audio is authored separately from visual layers. `AudioAsset` describes an immutable binary original with a rational playable duration, first source timestamp, sample rate and mono/stereo channel count. It has no visual dimensions, texture or data URL. `CompositionMotion.audioTracks` holds independent timed clips with name, source in-point, mute and gain. The visual hierarchy and z-order remain unchanged.

Imports prepare metadata before one reserved engine transaction and one atomic project/original IndexedDB write. They switch Static compositions to Motion through the existing first-conversion confirmation, place standalone audio at the playhead and extend duration when necessary. Trimming the left edge advances the source in-point; moving a clip preserves it. Static mode preserves all audio authoring and plays no audio. Undo/redo restores the complete transaction. Native originals are retained for history until project deletion, using the same tombstone and revision guards as video.

`compileMotion` always returns an `audio` array, empty for Static or legacy projects. Both video source audio and standalone clips use one headless Mediabunny mixer. Intervals are half-open and evaluated on an integer sample clock. Gain, mute and original source PTS are shared by live playback and export. The mixer retains at most four source readers with LRU eviction; sequential sounds are not limited to four originals. PCM is decoded in windows of at most one second and resources are closed explicitly. Audio PCM access is unrelated to GPU pixel readback.

The platform playback adapter schedules bounded PCM blocks through native WebAudio time. It has no React state or authored-frame commands. Pause, seek, loop boundaries, project changes and disposal retire scheduled nodes and reject stale asynchronous work. Export uses the original media through the same mixer, independent of the preview clock.

Each clip may author rational fade-in/fade-out durations and a bounded reverb wet amount/decay. Shared deterministic DSP runs in the audio worker for playback, isolated audition and Mediabunny export. Fades use the authored clip boundaries even when the composition ends early. Reverb state and seek preroll are bounded; wet/dry, fades and gain apply in the same order for every consumer. The standalone `@musart/render/audio` entry keeps Three.js and visual effect modules outside decoder workers.

The shared Volume popover uses the application's glass slider, exposes 0–100 percent, and synchronizes numeric input, thumb and output through a small presentation store. Preview changes publish no document commands or parent React updates. Completing a gesture creates one validated command and one undo step. Cancellation removes the draft. An open menu captures its immutable project/page/track origin; only recognized volume/mute changes can rebase that lease. Reloads with the same IDs, other edits and page changes invalidate old callbacks.

Volume/mute commits and their undo/redo preserve the transport clock, evaluated visual objects and audio worker. A specialized strict scalar-change policy rebases only compiled audio metadata; timing, assets, processing and visual edits retain the normal pause/recompile behavior. Muted/zero-volume clips open their original lazily when they become audible. Native scheduling uses 1,024-frame blocks, a 10 ms initial lead, 40 ms lookahead and a 10 ms pump, with at most four scheduled nodes. At 48 kHz, the queue horizon is bounded by about 61.4 ms; this is an audio scheduling bound, not a measured interaction-latency guarantee. Worker close failures propagate while termination and listener cleanup still run.

Waveforms prepare in one dedicated worker with a bounded queue. Each cached envelope contains at most 2,048 peaks, never the full decoded song. The result cache is limited to 1 MiB and 64 entries. Visible timeline rows draw a smooth symmetric mountain envelope only for the portion intersecting their horizontal viewport, using two nearby audio-color shades; hidden rows do not render waveforms. Preparation is interrupted when playback starts or the project changes. Waveform caches remain platform presentation data and never pollute undo, portable documents or the render graph.

The built-in bank contains original MusArt TypeScript synthesis recipes in the repository's MIT license. Seeded noise, oscillators and click-free envelopes render at a fixed 48 kHz into real PCM16 WAV originals. Whoosh, impact, pop, riser and tone categories need no third-party recording attribution or external generation service. Only the requested sound is synthesized, in the worker. These files are imported and persisted through the normal original-media lifecycle.

Hovering or focusing a bank item waits 150 ms before auditioning; the explicit Play button starts preparation inside its native user gesture. Opening the bank attempts to unlock the native audio context. A blocked context offers an explicit Play retry, and tab/browser mute remains under browser control. One audition can exist at a time. Leaving the item, closing the bank, hiding the page, changing category or switching documents immediately retires its generation and scheduled source. Late worker results cannot start the retired sound or replace its successor's waveform.

The worker returns each SFX WAV together with at most 512 genuine source-envelope peaks. Sound and waveform requests share one job and one cache entry; their combined bytes count against the existing 1 MiB bound. Audition decodes the actual WAV in the existing Mediabunny mixer worker, then transfers bounded PCM for native scheduling. It never calls main-thread `decodeAudioData`. An abortable native-resume wait lets closing the bank retire preparation even when browser sound permission leaves `resume()` pending.

**Sound Playground** is a six-second audio-only Motion template with three original WAV sidecars, nine timed cues, three grouped visual instruments, animated properties, GPU transitions, clip fades and shared reverb. Its source and auditable transaction batches are generated entirely through public headless core commands. The normal atomic media-template loader validates the exact WAV hashes and installs all originals together; audio-only projects do not need an unrelated video asset.

The Cinetic skill's sound reference informed placement, envelopes and sound roles. Its film-generation scaffolding, palette restrictions and renderer choices do not apply to this editor. No Remotion/HyperFrames engine or voice generation was introduced.

References: [Mediabunny reading media](https://mediabunny.dev/guide/reading-media-files), [WebAudio source scheduling](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/start). Native decoded export tests are required to demonstrate audible output; mocked mixer tests establish timing and lifecycle logic only.
